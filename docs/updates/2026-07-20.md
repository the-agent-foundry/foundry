# 2026-07-20 update notes

This update adds three reusable operating patterns: model-calibrated engineering governance, exact-route model onboarding, and a matter-isolated legal operator / executive counsel desk.

## What changed

- Expanded the engineer archetype beyond generic “keep going” instructions.
- Added one structural governance core for all models, with separate steering for completion-capable and hesitant models. The redesign was driven specifically by Victor's move to GPT-5.6 and applies to other models that push approved jobs through completion more reliably.
- Added frozen acceptance, direct/adjacent/review-machinery finding taxonomy, retained-work checkpoints, parent follow-through, complete-generation activation, and rollback/readback contracts.
- Added a model-onboarding skill and synthetic source-ledger/evaluation/activation/drift fixture.
- Added the sanitized Gideon legal-operator archetype with positive duties, primary-source discipline, matter isolation, public/private mode separation, hard external-action boundaries, and co-equal safety plus over-conservatism evaluation.

## Model compatibility recommendation

Do not preserve an entire legacy engineer config for an older model.

Use:

1. the modern governance core for every model;
2. a bounded completion-support module for models that stop early;
3. tighter scope ceilings and less motivational prose for models that naturally push work through completion;
4. fixed completion-and-restraint evaluations before changing the live profile.

The safe hybrid is modern governance plus bounded legacy completion support. Combining the new controls with old unlimited-work language can make a stronger model over-execute.

## Privacy posture

This public batch preserves patterns, schemas, archetypes, and synthetic fixtures. It excludes private profile prompts, live runtime config, credentials, provider account details, private model routes, internal paths, chat IDs, customer/company data, raw logs, run records, and real legal matters.
