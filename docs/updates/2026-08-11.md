# 2026-08-11 model-selection operating system

This update adds a maintained decision surface for choosing model candidates and binding exact routes when creating crons, tools, profiles, reviewers, and subagents.

## Why it exists

A model name is not a route decision. Real selection depends on endpoint, tools, privacy, entitlement, cost basis, workload, completion, restraint, latency, fallbacks, and verification. Public leaderboards collapse those variables into one shiny number and then age like gas-station sushi.

The new package gives founders and their agents a reusable method instead:

- public baseline roster;
- private local overlay;
- route-aware cost/benefit framework;
- explicit official, observed, and editorial evidence labels;
- family-level prompting guidance;
- specialist image/video/audio appendix;
- synthetic selection record;
- monthly freshness contract;
- deterministic renderer, validator, and adversarial tests.

## Public/private split

The public roster describes selected first-party API model candidates documented by providers. It is not an executable route registry and does not claim local credentials, account entitlement, runtime validation, negotiated prices, or private evaluation results.

Operators copy `local-overlay.example.json` to a private location and add their actual access, accounting model, approved data classes, validation state, measured quality, latency, accepted-outcome cost, and fallback.

## Editorial posture

Agent Foundry makes opinionated best-fit recommendations because neutral vendor soup is not useful. Every recommendation is labeled `editorial` unless a fixed public evaluation supports an `observed` label. Model identity and list-price claims remain bound to official sources.

## Scope

The main roster covers agent-capable language-model candidates. Image, video, audio, embeddings, moderation, and other specialist candidates stay in a separate appendix because their units and quality criteria differ.

## Maintenance

The roster is reviewed monthly and on major launches, retirements, pricing changes, route changes, privacy changes, or credible evaluation regressions. Stale review dates remain visible. Automation may identify that a review is due and prepare a proposal; it may not silently change recommendations, publish, merge, or activate routes.

## Safety

The package contains public provider facts, generalized editorial guidance, and synthetic examples only. It excludes private prompts, runtime adapters, local model assignments, credentials, account identifiers, negotiated rates, private evaluation inputs, raw usage, and billing records.

## Breaking changes

None. The package is additive.
